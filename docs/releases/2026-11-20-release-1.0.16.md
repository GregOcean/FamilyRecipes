## Mac 本地终端

先打开 Docker Desktop，待 Docker 就绪。沿用原 release 签名，不重新生成密钥。

```bash
cd /Users/wangyang/Documents/personal_projects/FamilyRecipes
bash scripts/prepare-release.sh 1.0.16
bash scripts/publish-release.sh 1.0.16
```

第一条脚本构建正式 APK、后端 JAR 和迁移包；第二条上传到 152.42.242.92 并执行服务器部署。出现密码提示时输入服务器 root 的 SSH 密码。只有明确显示“发布成功：1.0.16”才算完成。

本次包含 `2026-11-19-inventory-resolution.sql`。保留现有用户、菜谱和媒体；不清库，不重跑 schema.sql/data.sql，不重新导入菜谱。沿用现有邮件、AI 和管理员配置。后台静态页面随 JAR 部署，无需另开端口或构建前端。

## 验证

```bash
curl -fsS https://familyrecipes.live/apk/release.json
curl -fsS https://api.familyrecipes.live/api/config/catalog-summary
```

前者应显示 version 为 1.0.16；后者应返回 code 200 和菜谱数量。

## 未出现发布成功时

保留脚本末尾错误，不要清库。在 Mac 执行：

```bash
ssh root@152.42.242.92 'systemctl status familyrecipes --no-pager -l; journalctl -u familyrecipes -n 100 --no-pager'
```

服务重启后的短暂连接失败可能出现在健康检查轮询中，最终成功才是判据。迁移阶段失败会停止；应用更新阶段失败会尝试恢复旧程序和下载配置，不能仅凭上传完成判断上线成功。

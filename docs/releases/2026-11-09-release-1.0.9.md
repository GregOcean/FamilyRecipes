# 家肴 1.0.9 上线步骤

适用于当前 DigitalOcean 服务器 152.42.242.92、familyrecipes.live、MySQL family_recipes。Android versionCode=10，沿用原发布签名。已有 3k+ 菜谱和用户数据保留，不运行 schema.sql/data.sql，不重新导入目录数据。无需重新配置 Brevo 或更换模型密钥。

## 1. 本机打包

启动 Docker Desktop。在 Mac 终端执行：

```bash
cd /Users/wangyang/Documents/personal_projects/FamilyRecipes
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export ANDROID_HOME="$HOME/Library/Android/sdk"
bash scripts/prepare-release.sh 1.0.9
```

使用已有 android/keystore.properties。生成 familyrecipes-release/1.0.9，包括签名 APK、JAR、五份迁移、部署脚本和校验清单。若目录已存在，先确认是否是本次完整产物；不要直接覆盖或上传旧包。

## 2. 上传（仍在 Mac）

```bash
ssh root@152.42.242.92 'mkdir -p /root/familyrecipes-release/1.0.9'
scp familyrecipes-release/1.0.9/* root@152.42.242.92:/root/familyrecipes-release/1.0.9/
ssh root@152.42.242.92
```

输入的是服务器 SSH 密码。后续命令在服务器终端执行。

## 3. 部署后端、官网及 APK（服务器）

```bash
cd /root/familyrecipes-release/1.0.9
bash deploy-current-server.sh 1.0.9
```

脚本校验包、备份 MySQL/旧 JAR/APK/Nginx、执行可重复迁移、重启后端、验证 API 和 APK 下载、更新官网 release.json 的实际发布时间。官网包含在 JAR 中，无需单独传 HTML。等待明确输出「发布成功：1.0.9」。SSH 断开或只看到校验 OK 不代表发布成功。

此次延续之前已确认的公开权限调整：历史 private 菜谱会变成 public，group 菜谱不变。脚本部署应用失败会尝试恢复旧应用和下载配置；数据库迁移不会自动回退。备份位置以脚本输出为准。

## 4. 开启缺失标签补全（服务器）

新版确认启动后：

```bash
vim /etc/familyrecipes/ai.env
```

保留已有所有配置，添加或更新这两项，避免重复：

```dotenv
RECIPE_CLASSIFICATION_ENABLED=true
RECIPE_CLASSIFICATION_POLL_MS=10000
```

沿用文字模型补全口味/菜系，会产生模型调用费用，每次一条、调用结束后至少等待十秒；不覆盖明确标签，失败最多三次，不确定的留待审核。已有 systemd 90-ai.conf 读取该文件，无需重新创建。保存后：

```bash
chmod 600 /etc/familyrecipes/ai.env
systemctl restart familyrecipes
systemctl status familyrecipes --no-pager -l
journalctl -u familyrecipes -n 60 --no-pager
```

等日志显示 Spring Boot 启动完成，再进行下面验收；瞬间 active 不等于应用已经就绪。若外部 application-prod.yml 显式覆盖 app.classification 配置，需同步调整该项。不要打印或分享密钥文件。

## 5. 验收

服务器执行：

```bash
curl -fsS https://familyrecipes.live/apk/release.json
curl -fsS https://api.familyrecipes.live/api/recipes/search
mysql family_recipes -e 'SELECT status,COUNT(*) AS count FROM recipe_classification GROUP BY status;'
```

release.json 应显示 version=1.0.9 和本次发布时间；搜索应返回业务 code=200。分类进度中 complete 为已补齐，needs_review 为证据不足，failed 为失败（最多三次，间隔十分钟）。全量需要时间，不能把尚未处理理解成分类故障。

手机打开 https://familyrecipes.live/ 下载并覆盖安装，不卸载。设置中确认 1.0.9 (10)，检查：

- 应用名称和图标文字为「家肴」。
- 邮箱验证码、登录、搜索、好友邀请和群组加人。
- 菜谱口味/菜系逐步补齐且筛选有效。
- 同一 YouTube 视频直接点击与复制打开是否一致。
- 点菜默认名称、菜品列表及发送入口。

若要暂停标签补全，将 RECIPE_CLASSIFICATION_ENABLED 改为 false 并重启。不要反复重新导入菜谱。没有必要为本次重新跑全量翻译。

## 6. 失败时

保留部署报错位置和备份路径，不清库。查看 `journalctl -u familyrecipes -n 100 --no-pager` 与 `nginx -t`。脚本报告已回滚仍需检查服务和官网下载；数据库恢复需单独评估，避免覆盖发布后新增的用户数据。

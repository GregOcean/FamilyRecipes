## 真实 HTTP 流程

用两个仅存在于验收库的账户操作：

1. 请求注册验证码 → 从本地邮件箱读取 → 注册 → 登录 → 自动生成个人厨房。
2. 搜索/发送好友邀请 → 另一账号接受 → 创建包含好友的群 → 查看成员；成员响应不包含邮箱。
3. 同一消息请求重复提交只得到同一条消息；历史、未读及已读游标一致。
4. `Meiji milk 2 bottles` 匹配牛奶，`胡萝卜2根` 匹配胡萝卜，`鱼香茄子` 不被误认成鱼。
5. 使用同一入库请求 ID 重复提交，不产生第二条库存。
6. 管理员读取硬件、JVM、API 流量和 MySQL 指标；普通用户访问管理接口返回 403；暂停翻译队列可读取到真实状态。
7. Chrome 使用真实登录访问五类监控；无 JS 错误；390 宽度无横向溢出。

## 尚需真机/上线后验收的边界

- 未验证 vivo 相机硬件、厂商后台保活和真实手机输入法；未接厂商推送，WorkManager 不等于即时后台推送。
- 本轮没有调用收费 OCR/视觉或翻译模型；验证的是入口、任务路径、结构校验、缓存、匹配和失败处理，不代表识别准确率已经提高。
- 模型尚未返回翻译时允许保留原文。标准 ID 仍独立于显示语言，未知品牌商品需要用户确认映射。
- 库存过滤判断品种存在，不做食材重量/单位换算或精确营养、采购数量计算。
- 没有生产流量压测、真实 DNS/SMTP 供应商或旧版本全量数据库恢复演练。

## 食材关联规则

1. 菜谱食材、库存及扫描结果使用标准食材 ID 关联，显示文本不作为唯一身份。
2. 包装上的品牌、原商品名称保留；识别出明确的基础食材时关联标准词条。
3. 无法确定的内容不强制归类。例如“鱼香茄子”不能因为含“鱼”就认成鱼；调味奶也不能直接归为原味牛奶。
4. 用户确认的对应关系记入该用户的别名表，之后可复用。
5. “库存匹配”表示已知食材是否存在，不等于数量足够，也不表示所有食材可互相替代。保质期是可编辑估计，无法确定时留空。

## 管理后台

入口保持 `/admin/`，沿用 App 管理员账号与 `CATALOG_ADMIN_USER_ID`，没有新增默认管理密码。

采用深色分区看板，支持 5/10/30 秒刷新、手动刷新、暂停自动刷新。刷新失败保留上次数据并明确显示时间。

- **机器硬件**：CPU、核心数、负载、内存、磁盘、网络速率。Linux 使用可回收缓存口径的 MemAvailable；系统不支持的指标显示不可用。
- **应用健康度**：运行时间、JVM 内存、线程、死锁、GC。
- **应用流量**：最近 60 秒请求速率、平均/P95 耗时、4xx/5xx、处理中请求、接口排名和请求/响应字节量。采用有界内存窗口，无需独立监控数据库。
- **特殊任务**：翻译、菜谱分类/食材提取的状态计数、暂停/恢复、失败重试；图片与教程补充保留逐批、逐菜谱进度和审核入库。
- **数据库**：连通耗时、连接池占用/等待、MySQL 连接/慢查询/行锁和表体积。

流量仅覆盖此 Spring Boot 应用的 API，不包含 Nginx 直接服务的 APK、WebSocket 帧或机器上的其他服务。监控轮询不计入业务流量。任务暂停不终止正在进行的模型请求；内存暂停状态重启后按服务器配置恢复。

保留原有记录；无需清库。新版入库客户端依赖新版后端，应先迁移并更新后端，再分发 App。没有开启任何新的全量翻译、抓取或收费模型任务。

## 验收与实际边界

验收记录见本目录 `validation.md`。

本轮最终自动化结果：后端 123 项、Android 33 项测试通过；真实本地 API、Chrome 管理页和 Android 模拟器人工操作验收通过。截图在 `screenshots/`。

- 模拟器不能覆盖 vivo 等厂商系统全部行为，尤其后台限制、相机硬件和输入法。
- 后台消息目前由 WorkManager 调度；没有配置厂商推送，因此不能承诺被系统杀死后仍实时通知。前台同步、离线待发与重新进入后的补消息是本轮覆盖范围。
- 相册发送的表情图片仍属于持久化的消息附件，不会加入独立收藏表情库；未将其改成阅后删除，以免破坏收件人的离线补消息。
- 内容翻译复用现有异步队列。模型未启用、翻译尚未就绪时不会凭空生成译文；界面文案本身有中英资源。
- 免费图片和外链搜索是候选补充流程，需管理员确认；不会自动保证所有菜谱都有授权图片或有效视频。

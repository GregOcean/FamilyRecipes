# 单人使用与默认厨房

日期：2026-11-01。

## 行为

- 注册成功时，在同一事务里创建“我的家庭”单人群组和“我的厨房”。本人为管理员，上限仍为 10 人，可后续邀请家人，不要求先添加好友或发起群聊。
- 已有账号访问厨房列表时，如果没有任何可访问的厨房，自动补建。已有厨房不重复创建；曾选中的厨房仍可访问时保留选择，否则选择列表中第一个可访问厨房。
- Android 登录成功及进入主页面时加载厨房并自动选择，库存可以直接使用该厨房。初始化失败会提示重试。
- 新增厨房时，仅有一个自己管理的群组则直接输入名称；多个群组可选择归属；没有自己管理的群组，也可以直接创建厨房，后端同时创建单人群组。
- 一个群组仍可拥有多个厨房。库存权限仍由成员关系决定，单人初始化不会向其他用户开放内容。

## 实现约束

服务端在账号行上加事务锁，串行化同一用户的首次初始化，避免并发请求创建重复默认厨房。注册、默认提醒设置、群组成员、默认厨房与验证码消费一起提交。自动初始化不发送聊天消息。

`GET /api/kitchens` 保证已登录用户至少有一个可用厨房；`POST /api/kitchens` 的 `group_id` 可省略，表示创建独立的单人家庭与厨房。指定群组时仍校验管理员权限。

客户端初始化响应会检查当前账号和厨房选择，避免旧请求覆盖用户的新选择。个人厨房仍使用统一的群组权限模型，暂不增加另一套个人权限体系。

## 验收重点

1. 新注册账号无需建群、选厨房，直接添加食材。
2. 无厨房的旧账号登录后获得默认厨房，重复加载不会新增群组或厨房。
3. 仅有一个家庭时新增第二间厨房，无需先到聊天页面操作。
4. 其他用户不能读取个人厨房；邀请加入后沿用已有共享库存权限。

## 本轮验证结果

- 后端 34 项测试通过，包括真实 MySQL 下的注册初始化、重复加载、无群组创建厨房、权限隔离与多厨房规则。
- Android debug 构建和 4 项单元测试通过，已覆盖安装到本机模拟器。
- 本地 HTTP 端到端验证通过：邮箱验证码注册 → 默认厨房 → 重复读取不重复创建 → 添加食材 → 读取库存。
- 本地后端已重启。完整手动 UI 验收仍由用户在模拟器中继续进行。

# 库存分类与查找

日期：2026-11-01。

## 目标与分类边界

分类首先帮助用户找到家中物品，也方便没有目标时浏览。原来的“原料 / 成品 / 无糖 / 中式 / 干货”等混合了种类、来源和属性，并把大部分物品藏在“原料”下面。

本轮改为 13 个平铺入口，不再需要展开二级菜单：

| 分类 | 边界与例子 |
| --- | --- |
| 蔬菜菌菇 | 新鲜蔬菜、鲜菌菇、腌渍蔬菜；番茄、香菇、泡菜 |
| 肉禽 | 肉、禽、内脏，以及腌腊肉食材；猪肉、鸡翅、培根 |
| 水产 | 鱼、虾、蟹、贝等水产食材 |
| 蛋奶 | 鸡蛋、牛奶、酸奶、奶酪、奶油 |
| 豆制品 | 豆腐、豆干、腐竹等；豆浆归饮品、豆豉归调味料 |
| 米面主食 | 米、面、面粉、面包和面皮；饺子皮不与成品饺子混为一类 |
| 水果 | 鲜水果；干果与零食坚果另列 |
| 调味料 | 油盐酱醋、香料和烘焙辅料 |
| 干货杂粮 | 干菌菇、干豆、杂粮及常见煲汤干料 |
| 零食坚果 | 饼干、糖果、坚果、果干等 |
| 饮品 | 茶、咖啡、果汁、酒、豆浆等；牛奶统一放蛋奶 |
| 熟食速食 | 成品饺子、丸子、午餐肉等，以及用户登记的熟食、剩菜 |
| 待分类 | 无法可靠识别的物品；后续可手动整理 |

这是一套面向家用查找的实用分类，并非严格的生物或营养学分类。储存位置仍单独记录；“无糖”“外卖来源”等不再占用同一分类维度。熟食速食是为方便寻找可直接食用或简单加热的成品保留的入口。

## 浏览和添加交互

- 库存提供名称搜索，与当前分类组合筛选。
- 分类旁显示当前搜索结果中的库存条目数，单位为“项”，不是食品数量或重量。
- 空分类、无匹配结果有文字提示。父类筛选仍支持所有后代分类，避免未来增加层级后再次漏项。
- 添加确认弹窗使用后端食材库搜索补全，支持后端已有别名匹配，不再使用客户端静态名称列表。
- 显示“已匹配：牛奶 · 蛋奶”或“新物品：请确认分类”。预览接口只读取，不创建食材。
- 输入变化取消旧请求，检查当前名称后再应用结果；网络失败保留输入、阻止未经确认的提交，并可点击提示重试。
- 分类选择随库存草稿保存；确认弹窗可滚动，避免小屏或键盘挡住操作。

## 标准分类与库存调整

公共食材保留标准分类。一条库存可以设置 `category_override_id`；有效分类为覆盖值优先，否则使用关联食材分类。调整只影响该库存，不会改掉其他厨房的物品或公共食材库。

库存卡片同时显示存放位置和有效分类。点击卡片编辑可以调整分类，或选择“跟随食材库”恢复默认。分类调整仍受厨房成员权限限制。

分类建议使用保守的明确关键词，并优先处理复合食品，例如番茄酱、牛奶巧克力、牛肉水饺。不能可靠匹配的名称进入待分类；不宣称 AI 自动识别或百分之百准确。

## 数据与接口

- `schema.sql` 增加库存分类覆盖字段；`data.sql` 更新分类及 423 种预置食材的归属。
- `GET /api/fridge/ingredients/preview?name=...` 返回已有食材或未保存的分类建议。
- 搜索优先精确名称和别名，避免精确结果被 20 条限制挤掉。
- 保存时由服务端统一解析名称或别名。查询失败不会被当成“食材不存在”而创建新记录。
- `backend/scripts/sql/inventory-taxonomy-v2.sql` 仅用于本次本地旧分类调整，保留食材与库存 ID；不是上线迁移框架，用户开始自定义分类后不要重复运行。

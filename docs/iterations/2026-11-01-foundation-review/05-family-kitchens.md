# 家庭厨房与图文收藏迭代

日期：2026-11-01。基于用户确认的新规则；按未上线、单机部署重构。保留 Spring Boot + MySQL，图片存服务器本地目录。未部署、未提交 Git。

## 本轮规则与实现

| 模块 | 当前行为 |
| --- | --- |
| 群组与厨房 | 一个群组有多个独立、可命名的厨房；创建群组时建立“家里的厨房”。群管理员创建、改名，成员可切换。群聊人数由服务端固定限制为 10，没有付费扩容。 |
| 库存 | 必须指定厨房；该厨房所属群组成员均可查看、修改、消耗、删除。创建者仅记录来源。`owner_user_id` 表示预留给谁，不授予或限制权限，可为空；指定时须为群内成员。修改库存不能顺带迁移厨房。 |
| 菜谱/收藏归属 | 新增独立 `kitchen_id`，不再拿厨房 ID 当群组 ID。厨房列表的菜谱查询在分页、计数前过滤厨房；全局搜索仍搜索有权看到的内容。已有公开/私有/群组可见性继续生效，收藏内容仍由创建者编辑。 |
| 教程收藏 | 每篇收藏最多一个外部来源，不建立跨平台“同一道菜”聚合。标题、正文可编辑，正文可保存自己的字幕、步骤、AI 总结；没有调用外部 AI，也不下载或播放视频。支持最多 30 张有顺序的图片，每张有分类与说明，点击图片可修改。 |
| 图片分类 | `cover`、`step`、`screenshot`、`cooking_record`、`inventory`、`sticker`、`other`；上传文件记录分类，收藏中的图片还记录该处使用分类、说明、顺序。当前表情包支持静态 JPEG/PNG，暂不支持 GIF 动图。 |
| 垃圾箱 | 移除已保存内容的最后一个图片引用时软删除。未曾关联的上传超过 24 小时后由后台扫描收入垃圾箱；保留 30 天后删除文件，保留数据库墓碑。仍被其他内容引用的图片不能进入垃圾箱。可在个人页恢复尚未物理清理的图片；恢复不自动恢复已删除的菜谱或库存。 |
| 提醒 | 默认未来 3 天到期的未消耗库存，每天本机时间 17:00 后最多通知一次；个人页可改时间、天数、开关。汇总所有有权访问的厨房。WorkManager 每 15 分钟检查，到点后执行，系统省电可能延迟，不使用精确闹钟。 |
| 聊天 | 只有群聊，允许两人群。用户消息仅文字、链接、静态表情包；服务端生成的系统消息保留。没有私聊模块。 |
| 断线补拉 | `GET /api/messages/sync?groupId=...&afterId=...&limit=200` 按消息 ID 升序分批返回，客户端持续补拉直到追平。200 是批大小，不是总条数上限。消息写入与群组变更使用群行锁，让同群游标按提交顺序前进。 |
| 待发送消息 | Room 持久化 outbox，消息带 UUID。服务端 `(sender_id, client_message_id)` 唯一，同一消息重试返回原消息；同一编号对应不同内容返回冲突。WebSocket 和 HTTP 发送都由事务提交后的事件通知在线成员，离线可靠性依赖数据库而非 WebSocket。单机暂不引入独立消息队列。 |
| 后台新消息 | WorkManager 周期同步群消息、重试 outbox；按群汇总通知，不为首次同步的历史消息弹通知。聊天菜单有通知授权入口。没有 FCM/厂商推送接入，不能保证退出应用后的即时通知，强制停止时无法运行。 |
| Android 状态 | 引入 Room，按服务器与账号隔离草稿、搜索缓存、聊天缓存和 outbox。文字编辑持续写入草稿，图片草稿使用本机私有文件；收藏/库存/聊天失败后保留内容。搜索使用 ViewModel + StateFlow + 生命周期收集，持久化最近搜索结果；刷新失败保留结果。库存、菜谱和推荐取消过时请求并检查请求版本，避免旧响应覆盖新状态。 |

厨房管理权限和垃圾箱 30 天是本轮采用的默认值，后续可以调整。

## 推荐与公共数据

- **库存 + 会做**：当前厨房可用、未到期食材与菜谱用料匹配，同时要求该厨房关联群组中有人标记会做；按用料匹配比例排序。不会把腊肉自动等价为鲜猪肉；暂无数量单位换算、替代食材或营养计算。
- **搜索**：保留按关键词、标签搜索的独立路径及最新结果缓存，没有混入随机推荐。
- **发现**：从所有可见菜谱中按收藏标签、烹饪记录和随机扰动混排，排除本人点踩内容；属于可解释的基础排序，不是机器学习推荐模型。每次返回最多 20 项。
- **冷启动**：`data.sql` 包含 423 个公共食材条目、常用别名、部分加工状态，以及 10 篇原创入门图文菜谱（文字步骤与用料）。覆盖常见肉类部位、腌制品、多种调味酱、主食等。公共菜谱没有登录账号，`creator_id` 为空，普通用户不能修改系统条目。
- 食材库还需持续校对、补全与同义词整理，不能视为世界各地食材的完整清单。可爱图标与整体 UI 评审另行开展，本轮未生成图标素材。

## 数据与部署

本轮**只支持新建测试数据库**，依次运行 `schema.sql`、`data.sql`。不要把它们作为现有数据库的升级脚本执行；没有制作旧数据迁移。SQL 明确使用 UTF-8，食材名称使用二进制排序规则的唯一索引，避免不同名称在宽松排序规则下被当成同一个值。

新增核心表为 `kitchen`、`recipe_image`；扩充库存厨房外键、菜谱厨房归属、消息幂等编号、媒体分类与垃圾箱时间戳。Android 本地新增 Room `local-state.db`。

媒体仍必须备份实际文件与数据库。垃圾箱恢复仅在文件尚未清理时有效；被客户端或第三方下载过的内容无法远程撤回。没有引入 S3、Redis 或其他常驻服务。

Android 状态层采用增量改造：搜索已使用 ViewModel/StateFlow，聊天同步逻辑在 repository，部分旧页面仍使用 Activity/Fragment 绑定式 UI，未重写为 Compose。后台任务具体到达时间与 Android 设备的通知权限、网络、省电策略有关。

## 本机验收顺序

1. 按 `backend/README.md` 启动新数据库、后端。Android 模拟器连接 `http://10.0.2.2:8080`；真机连接电脑的局域网地址。安装 debug APK。
2. 注册两个账号，添加好友，创建家庭群；查看人数上限 10。创建“市区厨房”“老家厨房”，切换后确认库存不会串。
3. 账号 A 添加库存并预留给 A。账号 B 查看、修改数量和日期、标记用完，确认预留标签不限制操作。无关账号访问应被拒绝。
4. 添加图文收藏，选多张图片，点击图片设置分类/说明、编辑正文、加一个来源。退出后重新进入，确认草稿还在；断网保存后重试。发布后检查详情图文和厨房归属。
5. 搜索 A 再搜索 B，快速刷新/切换页面；确认 A 的慢响应不会覆盖 B。断网重新进入同一搜索，确认显示最近结果且可重试。
6. 两台设备进入群聊，发送文字、链接、静态表情包。断网发送多条，杀进程后重新启动并联网；确认待发送消息保留、恢复后没有重复。
7. 让另一端在断线期间发送超过 200 条消息；重连后检查完整补齐。聊天菜单打开通知权限，退到后台验证周期通知；不要以即时推送标准判断当前 WorkManager 方案。
8. 设置提醒为稍后时间，加入未来 3 天到期的库存，确认一天仅一次；关闭开关后不应提醒。Android 系统可能延迟执行。
9. 删除收藏中一张不被别处引用的已上传图片，保存；到个人页垃圾箱查看、恢复。删除整篇收藏或库存同理。已物理清理的图片不能恢复。
10. 新账号无需添加内容即可在全局搜索中找到公共食材与入门菜谱；选择库存推荐时，没有库存或没人标记会做出现空结果是正常条件限制。

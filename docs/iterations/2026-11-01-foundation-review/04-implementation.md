# 第一轮实施：单机基础可靠性

日期：2026-11-01。基于 `b180637`，代码已实施并通过后端回归与两端构建；修改尚未提交、未部署，真机交互待验收。

本记录是当前实施口径；01 保留原始评审证据，02/03 保留长期设计与候选计划。与本文冲突时，以本文为准。

## 本轮约束

- 保留 Java 17、Spring Boot、MyBatis、MySQL 和原生 Android。
- 视为未上线系统：只支持全新数据库，无旧数据迁移、旧密码兼容或双版本 API 过渡。
- 只运行一个后端进程，群消息在进程内广播；不引入 Redis、队列或分布式锁。
- 图片放本机独立目录，无 S3、MinIO 等额外服务。
- 聚焦现有故障和权限漏洞；不做共享厨房新领域、推荐算法、页面改版或全面 ViewModel 重写。

## 已实施的设计

### 1. 身份与访问控制

REST 默认要求有效 Bearer JWT。只有公开菜谱读取、搜索、配置读取和图片读取入口允许匿名；图片入口内部继续检查归属或公开引用。无 token 不再冒充用户 1；错误 token 即使访问公开接口也返回 401。JWT 密钥必须由环境变量提供，启动时校验。

密码使用 BCrypt。注册密码最少 8 字符、最多 72 个 UTF-8 字节。用户实体的密码不参与 JSON 序列化，嵌套在菜谱创建者和厨师列表时同样生效。

菜谱读取规则：公开，或本人创建，或 `visibility=group` 且读者是所属/共享群成员。详情、列表、计数、全局搜索、标签和最近常做查询均应用规则。修改、删除和追加外链仅允许创建者；不存在与无权访问均使用 404。分享目标必须是创建者已加入的群。

库存权限依据 `user_id`；`owner_user_id` 只是当前已有的所属人标签，不授予读写权限。更新、删除和消耗都校验当前用户，并在写入 SQL 中携带用户条件。

库存分类暂时是预置配置，只保留读取和匹配接口，移除没有管理员校验的写入口。

### 2. 数据完整性

菜谱主对象仍按编辑表单整体保存；关联集合（标签、食材、步骤、厨师、外链）统一约定：

| 请求值 | 行为 |
| --- | --- |
| 未提交或 null | 保留原集合 |
| `[]` | 清空集合 |
| 非空数组 | 替换集合 |

更新放在一个事务内，先锁定菜谱、检查创建者，再写入。收藏/差评也以菜谱行锁串行化切换，避免并发请求重复插入、计数漂移。只有实际详情 GET 增加浏览数；创建/编辑后的内部读取不再累计。

库存补齐所属人、图片、分类字段与查询映射。Android 原有未完成的所属人选择引用导致编译失败，本轮先固定记录当前用户；不新增群成员选择交互。临期查询依据日期范围且排除已消耗，不再只查询 `normal`，因此列表刷新为 `expiring` 后仍可提醒。日期使用同一个业务时钟，默认 Asia/Shanghai，可用 `app.time-zone` 配置。为限制改动范围，本轮保留现有状态列和刷新过程；将生命周期与日期状态彻底分离仍为后续设计。

群组创建对成员去重、排除创建者、验证好友，再计算数量。容量由服务端固定为当前个人版的 5 人。成员变更先锁定群记录，避免同一单机内并发请求绕过容量和计数更新。

### 3. 本地媒体

写入：已登录用户上传 → 限制 10MB、2000 万像素 → 实际解码 JPEG/PNG → 重新编码 PNG → UUID 文件名 → `media_file` 记录上传者。文件名、扩展名、MIME 声明均不作为可信内容判断。失败时尽量删除当前文件。

读取：`GET /api/upload/files/{filename}`，由后端读取，不能由 Nginx 直接暴露媒体目录。上传者可读；图片被可见菜谱的封面、步骤或外链缩略图引用时，菜谱读者可读。未关联的图片只允许上传者访问，私有库存图片也仅上传者可读。修改菜谱或库存时，不允许引用其他用户的本地图片。

Android 仅给与 API 同协议、同主机、同端口的本地媒体请求附加 token，不向第三方缩略图站点发送凭证。图片响应使用 `Cache-Control: no-store`，Android 图片缓存按账号区分。客户端上传失败则中止保存，保留输入，不再悄悄丢图。

当前菜谱编辑器支持一张封面；多选时明确只选择第一张，不再上传多张而只保存第一张。库存上传的 URL 写入库存记录。本轮不添加相册、裁剪或新的图片展示布局。

运行要求：`MEDIA_DIR` 必须位于应用发布目录之外，并由运行用户持有写权限。备份时同时保存数据库与该目录。数据库与文件系统无法原子提交，进程崩溃、取消编辑和批量上传部分成功可能留下未引用文件；本轮不自动清理，避免误删。后续可按上传记录和引用关系实现延迟清理。没有对象存储时，独立磁盘目录比增加 MinIO 更符合当前单机规模。

### 4. 聊天

WebSocket 握手通过 Authorization 校验身份，连接属性保存 userId/token。SEND 忽略客户端 senderId；SUBSCRIBE、发送和广播均检查群成员身份，处理消息与广播前检查 token 有效性。当前客户端仅支持文本，服务端拒绝客户端伪造 system 消息。

发送后重新查询数据库，响应包含消息 ID、时间和发送者。REST/WS 共用 Spring ObjectMapper，消息字段统一为 snake_case。会话发送操作串行化，避免同一连接同时写入。

Android 由当前 API 地址构造 ws/wss URL；历史与实时消息按 ID 合并、去重、排序。输入在收到本人消息回显后才清除，断开或超时保留草稿。退出账号关闭连接，清除当前厨房选择。尚无可靠离线队列和自动重连；确认超时时用户应查看记录后再重试，避免重复发送。

已读目标必须属于当前群；读取位置只前进不倒退。历史和未读查询均要求成员身份。

### 5. 其他直接故障

- 修复小红书 `/o/...` 路径截断，并优先保留完整 URL。
- 自动网页抓取仅支持列出的平台 HTTPS 域名，逐跳校验重定向，拒绝内网地址并限制响应体/跳转次数；不支持站点仍可保存链接并手动填标题。未把抓取当作必需的保存条件。
- Fragment 请求绑定视图生命周期；取消协程不当作普通失败；finally 安全访问绑定。
- 后台提醒检查登录、开启状态和 API 结果，账号切换期间不推送前一账号结果；仍是 WorkManager 的尽力提醒，不保证精确分钟。
- Android HTTP 日志不再记录完整请求/响应；服务端默认 INFO。
- Android Gradle Wrapper 改为与 AGP 8.2 对应的稳定 Gradle 8.2，使用 JDK 17。[官方兼容表](https://developer.android.com/build/releases/agp-8-2-0-release-notes)

## 数据库与运行方式

唯一的新建库来源为 `backend/src/main/resources/schema.sql` 与 `data.sql`：前者完整建表、保留外键，后者只放公共配置和分类种子，不创建默认用户。启动时禁用 SQL 初始化，建表失败不忽略。

旧 `migrations/` 和 `schema_no_fk.sql` 只保留历史参考，不能与新基线叠加执行。无需在已有数据库上尝试执行本轮基线；按要求新建空数据库。

配置及命令见 [单机运行说明](../../../backend/README.md)。不需要替换框架，也没有改动 DigitalOcean、DNS 或线上服务。

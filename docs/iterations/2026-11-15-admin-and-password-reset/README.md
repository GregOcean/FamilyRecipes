# 管理后台与忘记密码（2026-11-15）

## 入口

部署新版后端后，访问 `https://familyrecipes.live/admin`。静态页面随 JAR 提供，无需另外构建前端或开放端口。账号使用 App 注册账号，必须匹配服务器 `CATALOG_ADMIN_USER_ID`；普通账号没有后台权限。登录凭证仅保存于当前浏览器会话，退出即移除。

App 登录页面新增“忘记密码”；网页入口为 `/reset-password.html`。注册与密码重置使用不同验证码，重置验证码10分钟有效、最多5次输入错误、单次使用。发送频率每邮箱每小时5次、每IP每小时20次、成功发送后60秒可重发。SMTP明确失败可立即重试，但仍计入每小时发送次数。未注册邮箱也返回相同提示，不暴露是否注册。

重置成功更新密码并增加账号认证版本，旧 JWT 失效，包括已建立聊天连接后续的凭证校验。重新登录即可。无需用户重新注册。

## 内容管理流程

1. “选择菜谱”：搜索中英文菜名，可查看封面、外链数量；跨页选择最多30道公开初始化菜谱。个人创作菜谱不列入批量管理。
2. “开始补充”：确认后排队，每台服务仅运行一个搜索子进程，最多5批排队或运行。
3. “补充任务”：查看进度、失败原因和候选；支持暂停与继续。服务重启把未完成的运行任务变为暂停，管理员决定何时恢复。页面每10秒刷新任务列表。
4. “查看候选”：手动勾选教程与一张图片，再确认入库。单独添加链接或图片也可以。入库保留已有封面，同URL链接和同来源图片不会重复添加。

搜索沿用 rules-v2，无 LLM 调用，智谱搜索API仍按次计费。中文B站优先，无匹配再查小红书；海外查YouTube；图片查Wikimedia Commons。现有对应链接、图片会跳过搜索。候选标题、摘要、排名只用于初筛，视频内容和可播放性未验证。

每批累计最多120次付费搜索尝试（缓存命中不计）、每道最多3次尝试、整批最长2小时。重试沿用本批缓存和额度，不自动创建新任务绕开限额。新建另一批有独立缓存和额度。失败任务达到上限后，查看缺口再决定是否需要新批次。

图片仅从固定 Commons HTTPS 主机下载，不跟随重定向；校验许可、10MB大小、2000万像素及PNG/JPEG格式，再存入现有本地媒体库。图片来源、作者、许可、重编码说明集中进入“软件说明 → 内容来源”，不插入菜谱正文。不是所有Commons候选都能成功导入（如格式或大小超限），此时保留候选供另选。

“服务监控”提供数据库连通性、进程运行时间、JVM内存、任务磁盘余量、搜索配置是否存在、翻译/补充队列和补充失败记录。它是应用内监控，服务停机时后台也不可访问；不等于独立的外部可用性告警系统。密钥、原始环境变量、原始服务日志不会返回给网页。

## 部署差异

正常使用已有 `prepare-release.sh` / `publish-release.sh` 发版流程。此次已经把 `2026-11-15-admin-and-reset.sql` 加入打包与部署迁移列表，新增验证码、认证版本、任务、图片来源记录表；**不清库，不重新导入菜谱**。先迁移数据库再启动新JAR，避免所有带凭证请求查询认证版本表失败。App需要更新才有原生忘记密码入口；网页与后台只需更新JAR。

沿用 `/etc/familyrecipes/ai.env` 中的 `CATALOG_ADMIN_USER_ID` 和智谱密钥。搜索专用 `CATALOG_SEARCH_KEY` 优先，否则使用翻译路由的 key（`TRANSLATION_LLM_KEY` / `ZHIPU_API_KEY`）。必须有智谱搜索服务权限，不能填其他厂商的 key。邮件沿用已配置的 `mail.env` / Brevo。

可选配置：

```ini
CATALOG_JOBS_DIR=/opt/familyrecipes/catalog-jobs
CATALOG_PYTHON=python3
```

默认路径为服务工作目录下的 `catalog-jobs`。部署脚本为已知服务器工作目录 `/opt/familyrecipes` 创建0700目录，所有者为 systemd 服务账号。自定义路径时需要自行赋予同一服务账号写权限。该目录包含任务快照、SQLite搜索缓存、候选与受限日志；不要经Nginx公开，也不要提交Git。建议与数据库和上传图片一起备份。

Python worker已随JAR内置，不用另装依赖包，只需系统Python3。旧的CLI入口仍可用，但准备改用网页时先停止旧的独立试点服务，避免重复搜索：

```bash
systemctl stop familyrecipes-catalog-pilot
```

旧 `/var/lib/familyrecipes-catalog-pilot` 结果不会删除，但不会自动迁入网页任务；网页新建批次有自己的缓存。

## 验收

- 普通用户进入后台API返回403，未登录返回401。
- 管理员选1至3道缺资料的菜谱，开始任务，查看搜索额度及候选，确认后检查App显示与内容来源。
- 关闭网页任务继续运行；暂停/继续、后端重启后的恢复均不丢缓存。
- 输入注册邮箱获取重置验证码，修改密码；新密码能登录，旧登录凭证不能继续使用；验证码不能重复使用。
- 不存在邮箱同样提示“若邮箱已注册”；验证码不出现在日志/数据库明文中。

已完成本地验证：96项后端测试（隔离MySQL，包括鉴权、重置、旧凭证失效、媒体入库/去重/许可保存），14项搜索脚本测试，Android debug构建，浏览器页面冒烟测试（固定API数据）。本轮未调用真实搜索API、未向真实邮箱发信、未部署线上。

浏览器测试：在 `backend/src/main/resources/static` 启动本机HTTP服务，然后 `ADMIN_UI_BASE=http://127.0.0.1:端口 node scripts/test-admin-ui.cjs`，Node环境需有Playwright及Chrome。测试不会访问线上或产生搜索费用。

## 2026-11-19 进度展示修复

原版列表只有整批状态，候选面板也不会自动更新，因此难以判断任务是否推进。新版列表每10秒显示完成数、失败数、搜索请求次数、当前菜谱及搜索平台/图片阶段；展开可看到每道菜的状态。暂停后不会把进度文件遗留的 running 误显示为仍在执行。进度文件读取失败会单独提示，不假报完成。

候选审核区域不随轮询重建，避免清空管理员的勾选；单独“刷新候选”按钮也保留已有勾选。旧worker产生的结果仍可显示数量和菜名，但详细搜索阶段要由新版worker启动的任务产生。此改动只需更新后端JAR（含网页和worker），无需App或数据库迁移。旧CLI任务仍不自动归入网页批次。

# 群聊补齐与收发修复

## 本轮行为

- 顶部显示群名与人数，右侧明确的“群成员”入口展示成员姓名、头像；无头像时显示姓名首字和有区分的浅色底。
- 点选成员、点击“@成员”或输入半角 `@` / 中文输入法全角 `＠` 可提及群内成员。消息携带用户 ID，同名成员不会混淆。编辑提及文字后不再保留错误的提及身份。草稿保留提及信息。
- 自己和对方的消息都显示姓名及头像；收到对自己的提及时显示“有人 @ 我”。后台同步通知同样能识别 @；仍沿用现有系统后台任务机制，不宣称即时推送必达。
- 输入区使用“表情 / @成员 / 分享”三个有文字的入口，解决旧表情按钮文字被挤没的问题。
- 内置 32 个 Unicode 表情（动物、食物、表情、爱心等），离线可选，可连续插入文字；具体图形由 Android 系统 emoji 字体绘制。这不是额外下载的 GIF 贴纸包。保留从相册上传 JPEG/PNG 表情图片的入口。
- 分享可以选择自己在各厨房保存的点菜、备菜，以及通过带筛选的菜谱选择器选择菜谱。未保存的草稿需先保存。选择后确认发送到当前群，不依赖当前首页选中的厨房。
- 点菜、备菜和菜谱以标明类型的链接卡片展示，点击进入对应页面。点菜/备菜显示标题、可选日期餐次及菜名摘要；完整内容以打开后的页面为准。
- 通过分享入口分享菜谱，会给当前群成员只读访问权，保留原作者编辑权限；退群后不再获得该群授权。点菜/备菜继续沿用原有分享权限逻辑（含关联私有菜谱可读）。纯手工粘贴链接不会自动扩大权限。

## 收发缺陷与修复

1. 旧 `Map<String, Any>` 发送参数会产生 Retrofit 不支持的泛型通配符；异常被吞掉后，只显示“待发送”。改为 `SendMessageRequest`，新增实际调用 Retrofit 的无网络序列化回归测试。
2. 发送失败显示状态和失败原因，提供“重试发送 / 取消这条待发送消息”；队列和原内容持久保存。
3. 服务端确认后，在同一 Room 事务中写入消息并移除待发送记录，避免中间空档；发送确认不推进收件游标，防止跳过其他成员的消息。
4. 分享也进入持久队列，使用 `clientMessageId` 幂等重试；来源菜单改名后重试返回原消息，不重复发送。
5. 已发送消息映射明确包含 `client_message_id`，本地观察结果可据此排除临时重复。
6. 发送时只清理匹配的旧草稿，不删除输入框后来产生的新草稿。自己刚发的消息会滚动到可见区域；阅读历史时，不因普通轮询强行滚回底部。
7. 群列表预览不显示提及的内部编码；群成员的本地头像图片允许同群成员鉴权读取。

## 数据与部署

新增表 `recipe_chat_share` 记录通过聊天显式分享的菜谱群组授权。完整建库脚本已包含；**已有数据库更新后端前**执行：

```sh
mysql -u 数据库管理员 -p family_recipes < backend/scripts/sql/2026-11-07-chat-sharing.sql
```

该脚本仅创建缺失的新表，不清空旧数据。本机开发数据库已经应用；线上未操作。后端、Android 应同时更新，旧后端不能处理新增菜谱分享入口。

`POST /api/meals/{id}/share` 保留旧请求兼容，新增可选 clientMessageId，并返回分享消息；新增 `POST /api/recipes/{id}/share-chat`。提及在普通文字中使用 `@[显示名](familyrecipes://user/ID)` 表达，界面仅显示 `@显示名`；服务端校验目标确实在群中，无需修改 message 表。

- 模拟器双账号本机验收群：收到 @ 消息；群成员点选提及；表情面板插入并发送；对方实际收到含正确用户 ID 的消息。
- 点菜、备菜、菜谱均从聊天选择发送；卡片类型和内容正确，点菜和菜谱跳转已实际打开。

- 原来卡住的“我要吃东西！”已在本地成功补发。

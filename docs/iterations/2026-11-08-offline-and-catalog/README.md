# 离线消息、菜谱紧凑展示与冷启动数据

## 本轮代码
- 群组列表改为先读 Room 快照，再联网刷新；请求失败保留列表，用可重试提示代替原始 DNS 异常。
- 列表与群成员缓存按服务器及账号隔离；消息页、群组页和后台同步保存列表。群成员缓存用于断网查看与 @ 选择。
- 聊天沿用现有持久化 outbox、clientMessageId 幂等发送及手动重试；发送失败显示感叹号。联网后现有前台/后台同步仍会自动重试，不是仅手动发送。
- 首次从未加载过群组的设备不能凭空获得列表，界面明确提示需先联网加载一次。
- 详情封面从 250dp 缩至 200dp，减少标签间距，浏览和收藏数量移到底部，保留正常文字大小。
- 菜系使用 cuisine 标签精确筛选，与现有权限、口味、库存条件组合。选项来自当前可见菜谱标签。
- 复制自己的版本原本已存在：公开菜谱可读，编辑只能由创建者执行；复制后归当前用户，默认私有，图片独立复制，原菜谱不变。

## 冷启动导入：待确认来源，不伪造完成
目标至少 1000 条，中华菜系占至少 50%，每条含封面和至少一张对应步骤的真实过程图。热门需要记录原站指标、数值、采集时间；不同站点不能直接比较收藏数/浏览量。按来源内热度及菜系配额选择，不能宣称全球最热门。

已调查：
- https://www.themealdb.com/terms_of_use.php 允许使用官方 API 返回的内容，禁止抓取其网站；公开发布还需结合订阅及署名条件。
- https://www.themealdb.com/docs_api_guide.php 提供国家/地区与类别、食材、菜品封面，未提供完整步骤图片集合的保证。
- Wikibooks Cookbook 是另一个候选，需逐条检查配图许可和内容完整度，不能保证步骤图与中华菜系配额。

尚未抓取 1000 条、尚未导入线上、尚未创建管理员账号。等待用户选择数据源/授权方式。
准备了 backend/scripts/seed/validate_catalog.py，对 JSONL 检查数量、来源去重、中华菜系占比、图文来源与许可字段、独立过程图、热门依据。它是初步质量门槛，不代替人工核实授权、图片内容和配方真实性。

后续流程：
1. 获取允许复用的来源，采集样本，人工审查内容和每张图片的许可。
2. 本地保存原文、修订版本、作者、出处、许可、热度证据、下载哈希与步骤对应关系。
3. 将 cuisine 标签归一，中华菜系分到具体菜系；其他国家菜谱同样保留地区与菜系信息。
4. 本地质量门槛 + 人工抽查；不达标候选不发布，不用封面或生成图冒充过程图。
5. 以专用内容管理员为 creator 建立公开菜谱，沿用创建者编辑权限；普通用户可收藏、复制自己的版本。
6. 先少量测试导入与媒体鉴权，再按批次/来源 ID 幂等导入；保留批次清单以便撤回该批，不清库。

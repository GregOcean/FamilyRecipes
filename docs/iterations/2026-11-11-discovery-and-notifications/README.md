# 分类、库存匹配、草稿与收藏通知（2026-11-11）

本轮为本地实现，尚未发布线上。升级需要同时发布后端与 Android；不需要重新导入或翻译整个菜谱库。

## 功能

- 家常菜独立为一级，允许与地域菜系并列。中国保留八大菜系；港澳台并入其他省级风味；东北、西北、京津冀、云贵合并。亚洲三大区域合并入口；印度仍单列；欧洲为东、南、西、北欧；大洋洲、非洲、美洲、中东简化。
- 旧标签和国家代码通过别名映射继续匹配，例如辽宁菜→东北菜、法国菜→西欧、澳洲→大洋洲。不会删掉用户原标签。
- 口味按酸、甜、苦、辣、鲜香、清淡、麻、咸、臭排序。耗时含 ≤60 分钟与 >60 分钟，未知耗时不参与限时结果。
- 库存：不限 / 食材齐全 / 允许缺少食材（至少有一样）。后者要求当前厨房至少一项有效库存与菜谱食材共享 ingredient_id；过期或已消耗不算。旧客户端 missing=2 仍保持原含义；新客户端使用 missing=-1。
- 首页筛选为“类别 + 当前值”两行，换一批移至发现/我的菜谱同行，加载更多随列表滚动，不再占固定底部空间。
- 安排为点菜→备菜→草稿；草稿只包含安排。菜谱、做菜记录草稿移到“我”的草稿入口，删除均有确认。
- 消息页分通知、群聊；别人收藏作者的菜谱时写入收藏通知（不通知自己；同人同菜谱取消再收藏不重复通知）。支持账号隔离、分页、未读数、本地缓存、后台轮询和系统通知。系统通知依赖 Android 通知权限与系统后台调度，并非独立推送服务。

## 后台内容补全

`RecipeEnrichmentService` 替代旧定时分类及 v2 细分任务，使用现有 translation LLM 路由。满足 `RECIPE_CLASSIFICATION_ENABLED=true` 且模型/key 已配置后运行。

- 旧菜谱没有 v3 记录时自动进入候选，新菜谱自动进入；编辑后失效重算，优先最近修改。
- 一次请求返回多个口味/菜系、预估总耗时、原文明示的食材。只补空耗时；保留已有标签，追加去重后的新标签。
- 保存前锁定菜谱并比较标题、正文、步骤、食材、标签及耗时快照，编辑期间返回的旧结果丢弃。
- 食材先复用既有名称/别名；具有原文证据且模型置信度 ≥0.9、标记为食品的规范名称才进入公共食材库并关联菜谱。低置信度候选留在 result_json，标为 needs_review；模型置信度不是质量保证，仍需抽查。
- 仅有外链而没有可读内容的菜谱，不能可靠提取食材或时间；保持未知。不限库存仍能找到，库存约束下不会伪造匹配。
- 单机串行，每次最多一个任务，间隔复用 `RECIPE_CLASSIFICATION_POLL_MS`（默认10秒），失败10分钟后重试，最多3次。任务不阻塞首页请求。现有内容量大时全部补全需要时间及 API 用量。

管理员接口（带现有管理员 JWT）：

- `GET /api/catalog/status`：enrichment_version、未入队数、各状态数量。
- `GET /api/catalog/enrichment/review?afterId=0`：失败/待复核的结果与候选食材，每页100条。
- `POST /api/catalog/classification/retry`：重新排入失败/待复核任务，不重跑已完成任务。
- 旧 `POST /api/catalog/cuisine-refinement` 返回409，防止继续排入已停止的 v2 细分队列。

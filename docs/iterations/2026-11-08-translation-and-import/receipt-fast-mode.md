平均 6.60 秒；上一版开启推理平均 87.23 秒，且第 3 张输出截断。这是单轮观察，不是延迟保证。

局限：前两张食品过滤失效（纸巾、清洁用品混入）；储存方式和保质期出现空值，名称、数量仍有误读。精简任务不等同于完成食品语义识别。原始输出保留在当前忽略目录下的 results.json。

后端已支持 vision.thinking-type，默认 disabled；翻译路由保持原设置。提示词保存于 backend/src/main/resources/prompts/receipt-inventory.txt。上述四张对比为当时的 API 直连测试；随后已补齐 App 流程，见下节。


## 2026-11-08 补齐业务链路与本地验收

- Android：`＋ → 食材 → 小票识别入库`。系统选图、相机拍照；按 EXIF 旋转并压缩图片；结果可修改名称、数量、储存方式、预计天数，也可移除误识别项。空值不伪造估计，入库前补齐。
- 草稿按账号及厨房隔离保存。退出、进程重启与覆盖安装后保留。发起入库前固化请求 ID 和内容，结果未知时重试相同请求，避免重复入库。
- 后端 `POST /api/receipts/recognize`：厨房成员鉴权、8MB JPG/PNG 与图像尺寸限制、最多两个并发视觉调用、直接使用已批准的精简提示词，不启用推理。
- 后端 `POST /api/receipts/import`：批次字段校验、事务、请求指纹和去重台账；新增 `2026-11-08-receipt-import.sql`。名称最多50字，与现有食材表一致；数量最多50字；天数1–3650。库存到期日从入库当天算。
- 后端不把小票照片保存为媒体或库存图片；本机临时照片用于失败重试，入库成功时删除。密钥仅留服务端。
- 真实本地联调：从模拟器选择用户提供的 NTUC 小票，经本地后端调用真实 GLM-4.6V-Flash 返回5项（仍包含一项清洁用品、缺少储存估计，此处效果问题未掩盖）。测试移除其他项，保留红糖 `T OKINAWA BRW SGR / 4X340`，填写常温、90天；覆盖安装新版 Debug 后草稿字段恢复，确认入库成功。
- 本地库核验：该测试库存为2026-11-08购入、2027-02-06到期，`receipt_import.item_count=1`。这是本地测试数据，未写线上。
- 61项后端测试通过；Android assembleDebug/testDebugUnitTest通过。新增测试覆盖识别请求传输、关闭推理、JSON解析、缺失估计、图片格式、未登录/非成员、重复入库、请求内容冲突及非法批次。
- 模拟器打开系统相机和取消返回通过；本轮真实图片识别验收使用系统相册，未用实体手机相机验收。物品照片识别不在本次业务交付范围。

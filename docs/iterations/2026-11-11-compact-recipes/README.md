# 菜谱展示空间与导入文本清理

## 页面调整

- 首页取消正常状态的结果数量行及“换一批”按钮，列表顶部下拉刷新；保留搜索/筛选条件，刷新推荐种子。加载状态由刷新指示器展示，失败仍提供可点击的重试提示。
- 公共菜谱总量移至设置→软件说明，从匿名统计接口获取，只计公开菜谱；网络失败时不猜测数字。来源简写为 HowToCook、Wikibooks、UniTools 及用户贡献，不列章节URL。详细版权/来源元数据仍在独立来源说明页。
- 详情页顶部去掉重复标题，缩小创建者信息区；标签移至正文、步骤和外链之后，按展示文字去重（兼容不同原标签映射成同名）。
- 收藏、踩、更多三个按钮等宽，48dp 高；底部边距缩小。一级导航从78dp压到60dp（不含系统安全区），保留文字及至少48dp点击目标。

## 扫描结果与处理范围

对本地已有快照扫描：27894段正文/步骤，789段含 `__notoc__`，1666段可做明确标记/前导竖线/空白格式清理，28段仍含模板括号，保留人工复核。

审计文件在忽略Git的数据目录：`data/seed-candidates/quality/2026-11-11-text-scan.json`。这些是本地源数据统计，不等同于线上中文译文数量。

`__NOTOC__` 是 MediaWiki 控制目录显示的指令，不是菜谱正文。新增 `recipe_text.py` 去掉明确的控制指令，不删除分数、单位、温度、正常标点或未知模板内容。规范化导入流程同时修复嵌套模板解析，防止继续生成孤立的 `}}`。Android 展示层也过滤已知标记，便于旧数据在数据库清理前正常阅读。

## 线上数据库清理（独立执行）

本次仅本地测试，未修改线上数据库。新发布包会带上 `clean_imported_text.py` 和 `recipe_text.py` 并纳入 SHA256 校验。

在完成新版本发布后，服务器进入对应发布目录，用 root 的本地 MySQL socket 执行：

```bash
# 先扫描；不修改数据库
python3 clean_imported_text.py --report /root/recipe-text-scan.json

# 查看 safe_changes / manual_review，或用 vim 打开报告
vim /root/recipe-text-scan.json

# 确认后只应用规则确定的格式清理
python3 clean_imported_text.py --apply --report /root/recipe-text-applied.json
```

报告文件必须使用未存在的新文件名，避免覆盖审计记录。`changes` 留存修改前后全文；`manual_review` 只列问题，不自动删除。脚本仅修改有来源记录的导入菜谱正文/步骤及对应译文，不改个人原创内容，不删除菜谱。数据库更新在一个事务内，并比较原文，跳过扫描后被并发编辑的字段；重复执行不会反复修改。

正文改变后会失效对应自动补全任务。翻译按源内容hash匹配，因此变动的段落可能需要后台重新翻译；旧翻译记录保留，不全量重翻。
